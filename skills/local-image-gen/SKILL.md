# Local Image Gen（img-forge）

Apple Silicon MacでSDXL系のモデルをローカル実行し、課金ゼロ・枚数無制限で画像を生成する。
単発生成・夜間バッチ・モデル追加・ダッシュボード起動までを担当する。

## 依存

- `img-forge` 本体（generate.py / fetch_model.py / dashboard.py / models.json / .venv）
  - **設置場所はユーザーに確認するか、`~/Developer/img-forge` を既定として探す。** 見つからなければユーザーに場所を聞く
- モデル実体の置き場（既定 `~/AI-Models/`）
- 登録済みモデルと品質タグ・ネガティブの正本は `models.json`（このスキルに転記しない）
- 各スクリプトの引数の正本は `--help`（実行前に必ず確認する）

## 大原則

1. **プロンプトは本文タグだけ渡す。** 品質タグ・ネガティブは `models.json` から自動で付与される。二重に足さない
2. **枚数を惜しまない。** ローカル生成は無料。破綻画像はバッチの平常運転なので、多めに焼いて人間の目で選ぶ前提で組む
3. **5分を超える見込み（目安10枚以上）はバックグラウンド実行**にして、完了時に報告する

## ワークフロー

### A. 「こういうイメージで100枚焼いといて」（このスキルの主用途）

ユーザーが日本語でイメージだけを伝えてきたら、**プロンプトの作成から実行までを引き受ける。**

1. **イメージを分解する** — 被写体・構図・服装・表情・光・背景・画風の軸に分ける
2. **バリエーション軸を決める** — 何を振るのかをユーザーに一言で示す（例:「髪型と衣装と光を振って100本作ります」）
3. **プロンプトファイルを書く** — 1行1プロンプトのテキストファイルを作る（`#` 始まりの行はコメントとして無視される）
4. **バックグラウンドで走らせる**
5. **完了したら、総枚数・所要時間・出力フォルダを報告する**

```bash
cd <img-forgeのパス>
.venv/bin/python generate.py -m <モデル> --prompt-file <案リスト.txt> -c 1 --job <ジョブ名>
```

- 行数 × `-c` が総枚数。100行 × 1枚 = 100枚
- 所要時間の目安は **1枚あたり2分**（1024px級・26ステップ）。100枚なら約3.5時間。**走らせる前に見積もりを伝える**

**プロンプトを書くときの注意**

- **77トークンで後半が黙って切り捨てられる。** 重要なタグほど前に置き、詰め込みすぎない
- 実行ログの CLIP truncation 警告を確認する
- 「透明感」は肌の質感タグ（`translucent skin` / `dewy skin`）ではなく**照明のタグ**で出す（`backlighting`, `sunlight through window`, `light particles`）。肌タグを使うと腕がテカって不気味になる

### B. 単発〜少量生成

```bash
.venv/bin/python generate.py --help            # 引数確認
.venv/bin/python generate.py -m <モデル> -p "<本文タグ>" -c 4
```

- 生成サイズはSDXLの訓練域（約100万画素）内で指定する。大判が欲しい場合は生成後に拡大する
- 見せる用の絵は **人気マージモデル + `--hires`（拡大）** を既定にする。素体モデル（Illustrious / NoobAI など）はチューニング前の「すっぴん」なので、そのままだと物足りない絵が出る
- 顔が不要な絵（風景など）は `--no-face-fix` で速くなる

### C. モデル追加

```bash
.venv/bin/python fetch_model.py --help
```

- 追加前にモデル配布ページで**ライセンス（商用利用・画像販売の可否）と、推奨品質タグ、V-prediction の有無**を確認し、`--quality` / `--vpred` に反映する
- **V-predictionの取り違えは灰色の壊れた絵になる。** 同名モデルに通常版とVpred版の兄弟がいることがあるので、配布ページを正とする
- Civitaiの直接ダウンロードは認証が必要。先に Hugging Face のミラー（diffusers形式）を探すほうが早い
- ログイン必須モデルは環境変数 `CIVITAI_TOKEN` が必要。**キーをこのスキルやメモに平文で書かない**

### D. ダッシュボード

```bash
.venv/bin/python dashboard.py     # → http://localhost:3942
```

生成・レビュー（採用／ボツの仕分け）・モデル管理の3タブ。作業が終わったら停止したことまで確認する。

### E. スタイル（当たりプリセット）

- 「スタイル」＝ **モデル・LoRA強度・画風タグ・追加ネガティブ**の名前付きプリセット（正本 `styles.json`）。本文プロンプト（構図・シーン）は含まない
- Illustrious系のモデルは統一された顔を持たないため、指定しないと絵柄が毎回暴れる。**絵柄の固定は画風タグ欄で行う**

### F. XYZスイープ（新しいモデルの品定め）

新モデルの実力測定と当たり設定（CFG・ステップ数）探し。ダッシュボードの生成タブ「高級設定」内、またはAPIを直接叩く。

```bash
curl -s -X POST localhost:3942/api/sweep -H "Content-Type: application/json" -d '{
  "prompt": "1girl, kimono, night",
  "model": "<モデル名>",
  "x": {"param": "cfg", "values": ["4", "5.5", "7"]},
  "y": {"param": "model", "values": []},
  "width": 832, "height": 1216, "job": "shinsa"}'
```

- 軸は `model` / `cfg` / `steps`。モデル軸の values を空にすると手持ち全モデル。セル数上限30・全セル同シード固定
- 返ってきた `id` で `http://localhost:3942/sweep/<id>` の比較表を開く
- 表の「これを当たりに登録」→ `models.json` の既定cfg/stepsが更新され、**次回生成から自動適用**される

## トラブル時の初動

症状別の詳細は img-forge 同梱の `TROUBLESHOOTING.md` を読む。頻出はこの3つ。

- **真っ黒な画像** → fp16 VAEのNaN / clip_skipの二重掛け / 拡大用GANのGPU常駐、の3種類。いずれも本体側で対策済みだが、再発したらメモリ逼迫を疑う
- **異常に遅い（想定の5倍）** → 他のGPUアプリ（Draw Things / ComfyUI など）が占有している。img-forgeを止めた状態でGPU使用率を確認する
- **LoRAが効かない** → ロード成功と有効は別。同プロンプト・同シードでLoRAあり/なしのA/Bを焼いて目視判定する。ファイル名からの互換性判定は当てにならない

## 報告の作法

- 出力は `<img-forge>/output/<日時_ジョブ名>/` に溜まる
- バッチ完了の報告には **総枚数・所要時間・出力フォルダ** を含める
- 採用画像を別の場所へ移す運用なら、コピー先のパスを1行1ファイルで示す

## Tips

- モデルの絵柄比較は**同じ本文プロンプト＋同じシード**で焼くと差が分かりやすい
- 8枚以上焼くと自動採点（scores.json）が付く。報告時は点数順の上位から見せる
- ラフ検討は低ステップ（8前後・約20秒/枚）、本番は26前後、と使い分ける
